이 문서는 **`instruction` / `input` / `output` JSONL**이 어떤 **출력 성격(형식·문체·압축·정렬)**을 갖는지, 데이터 계약 관점에서 다섯 가지로 요약한다.

# 파인튜닝 출력 성격 (5가지, 요약)

`instruction` / `input` / `output` JSONL을 `train_lora.py`의 `example_to_text`로 직렬화해 학습합니다. **형식은 코드에 하드코딩되지 않고, 데이터 `instruction` 계약을 따릅니다.**

→ [어댑터 가이드](../adapter/LORA_ADAPTER_GUIDE.md) · [Colab](../colab/COLAB_TRAINING.md)

---

### 1️⃣ 형식 (Structure)

**메타 (`finetune_dataset.jsonl`)**  
`instruction`에 「절대 순서 — 4줄만」이 있으면 출력은 항상 **`title:` → `bc_id:` → `sc_keyword:` → `tl_summary:`**. ([안건분류]→[심사요약] 같은 고정 라벨은 이 데이터에 없음.)

**의회·검토 문서 (별도 JSONL 합칠 때)**  
행마다 목차가 다름(예: 제목·제안이유·주요내용·기대효과 / 사안 개요·현행 제도·검토 의견·정비과제 / 6단 등). 출력은 **`##` 소제목**으로 구획.

**추론**  
시스템 프롬프트에 같은 `instruction`을 넣으면 형식이 맞물림.

---

### 2️⃣ 문체 (Style)

**메타**: 인사·자기설명 금지, 근거 밖 추정 금지 등이 `instruction`에 명시.

**국회형 `output`**: `~함` / `~임` / `~됨` / `~보임`, `현행 제도는 …`, `…할 필요가 있음`, `타당한 측면이 있음` 등 검토서체.

**입력**: 대화체·이메일·「입니다/해주세요」는 `output`에서 **제거·치환** 쪽으로 학습.

---

### 3️⃣ Reduce (핵심)

- **메타**: 장문 → 제목·키워드·3문장 요약.
- **국회형**: 메모·불릿·표·대화 등 난잡한 입력 → **짧은 단락 + 불릿**, 한 흐름 문서.

중복 정리 · 조치는 불릿 · **현황→한계→검토→과제→기대**에 가깝게 통합 서술.

**주의:** 학습된 태스크·프롬프트에 종속. 데이터에 없는 형식은 **보장되지 않음.**

---

### 4️⃣ 논리 구조 (자동 정렬)

국회형에서 자주 보이는 축: **현안·현황 → 현행 제도·문제 → 검토·필요성 → 정비 과제 → 기대·종합·검토사항.**

입력 순서와 무관하게 **`instruction`이 정한 소제목 순**으로 배열.

**한계:** 모든 샘플이 **`가결/부결` 결론**으로 끝나는 구조는 `assembly_style_…` 샘플 기준으로 **의결 용어 중심 학습이라 보기 어려움** (결론이 기대효과형인 경우 많음).

---

### 5️⃣ 정책 문장 패턴

**많은 편:** `…할 수 있도록 함`, `…마련함`, `…부과함`, `…검토함` / `…필요하다·필요가 있음`, `필요성 인정`, `타당한 측면`, `제도 보완` / `기대된다`, `향상될 것으로 보임`.

**샘플에서는 거의 없음:** `가결`·`수정가결`·`부결`, `사료됨`, `촉구함` → 쓰게 하려면 **그 표현이 들어간 `output` 데이터 추가**가 필요.

---

**한 줄:** 주력 데이터 축은 **메타 4줄**과 **태스크별 `##` 목차**이지, 단일 [안건분류] 4단이 아님. 스크립트: `train_lora.py`, `train_lora_unsloth.py` · 데이터 예: `finetune_dataset.jsonl`, `assembly_style_instruction_dataset_450_train.jsonl`.
